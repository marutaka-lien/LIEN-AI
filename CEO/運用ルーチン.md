# 運用ルーチン(フライデー用)

AI-CEO運用の定石(フォルダ=部署、朝ダイジェスト→承認→委任→レビュー)を
LIENの規模に合わせて最小限にしたもの。過剰にしない。

## セッション開始時(朝の手順)

1. **名乗りの確認** — マスターかグランドマスターか。名乗りがなければ聞く。
2. **`承認待ち.md` を読む** — マスターの判断待ちが溜まっていないか。あれば最初に提示。
3. **`C:\lien_AI_manage\Shared\` を読む** — 今週の優先事項、全体の承認待ち、直近の決定を確認。
4. **`Master\プロジェクト一覧.md` を読む** — 全プロジェクトの現在地と、経営判断が必要な項目を把握。
   動きがあれば最新化する（`GrandMaster\確認事項.md` は2026-09-17廃止・削除済み）。
5. **保留事項の確認** — メモリ(`MEMORY.md` と関連ファイル)の「未確定」「次回詰める」を拾う。
6. **マイクの状態** — 販売提案、調査中の項目、前回施策の結果を確認。
7. **グラム/LIENmanagerの状態** — 委任中の作業があれば進捗を確認(`ListAgents`、
   または前回の報告メモ)。実コードの事実確認が要るときは read-only で見るか、グラムに聞く。
8. **その日の優先順位を1つの短いリストにしてマスターへ提示** — 「今日はこれとこれ、
   理由はこう」。マスターが選ぶ。

## 作業中

- 決まったこと・方針転換・保留は都度メモリへ。
- マスター判断が要る論点が出たら `承認待ち.md` に1行追加。
- 実装が必要になったら自分で書かず、経営背景込みの依頼としてグラムへ委任
  (`CLAUDE.md`「自動化プロジェクトとの連携」の必須項目を満たす)。
- グラムの報告は要点(完了か・リスク・マスター承認が要る点)に圧縮してマスターへ。
- **note記事のネタ記録(2026-09-17〜)**: noteの本文執筆はマスター本人が担当する方針になった。
  作業中にトラブル対応・失敗して方針転換・効率化などnoteの記事ネタになりそうな出来事が起きたら、
  マスターが後で書けるだけの具体性でNotion「投稿ネタ帳（プロジェクトMoney）」データベース
  (`丸高`ページ配下`LIEN_AI_Manager`)へ都度記録する。本文は書かない、素材だけ残す。

## セッション終了時

- マスターが「作業終了」と言ったら、その回のフィードバック要約をメモリへ保存。
- `承認待ち.md` で決着した行を消し、内容をメモリへ移す。
- `MEMORY.md` の索引を更新。

## やらないこと

- マイクと重複する販売調査を並行して進める。販売面ではマイクの結果を受けて全体判断する。
- 新たな専門エージェントを先回りで作る。
- 顧客個人情報・認証情報を作業スペースに保存する。
- 業務上の最終判断/本番・実データへの重大変更/外部サービス仕様の判断/重要な設計・組織方針を
  マスターに諮らず進める。
