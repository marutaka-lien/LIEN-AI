# 参考: RMS「発送完了報告データ(アップロード用)」CSV データ形式

出典: 楽天 店舗運営Navi マニュアルID 000038913（更新日 2025-06-23）
https://navi-manual.faq.rakuten.net/order/000038913
取得: 2026-09-07 フライデー（Claude in Chrome でマスターのセッションから読み取り。個人情報なし）

## 制約

- アップロード可能なのは **注文日を含め180日以内**。181日以上経過したデータは不可。
- 1度のアップロードで更新可能な上限は **レコード単位で5,000件**。
- **注文番号は必須**。
- データサイズは楽天ペイ受注管理画面の仕様に準拠。ダウンロードサイズとアップロード可能サイズは一致しない。
- 文字コード: Shift-JIS（アップロード画面に明記。UTF-8不可）。

## 1行目（ヘッダー、順序固定・改変不可）

| 順序 | 項目名 |
|---|---|
| 1 | 注文番号 |
| 2 | 送付先ID |
| 3 | 発送明細ID |
| 4 | お荷物伝票番号 |
| 5 | 配送会社 |
| 6 | 発送日 |

行の削除・項目名変更・移動・削除は不可。

**注意: このアップロード用CSVには 送付先氏名・住所・郵便番号の列がない。**
→ クリックポスト出力CSV（追跡番号＋宛先。注文番号なし）と、この6列だけでは直接突き合わせできない。
　注文番号 ↔ 宛先 の対応表が別途要る（下記「突き合わせの橋渡し」）。

## 2行目以降（データ）

### 必須

| 項目 | 内容 | 例 |
|---|---|---|
| 注文番号 | `店舗ID-yyyymmdd-******` | `290333-20230711-0709414358` |

### 条件付き必須

| 項目 | 内容 |
|---|---|
| 送付先ID | 送付先単位の番号。**指定なし → 「送付先1」に追加登録**。最大 半角数字10桁。「発送完了報告用」テンプレートのダウンロードで確認できる。 |
| 発送明細ID | お荷物伝票番号・発送日・配送会社の報告単位の番号。半角数字12桁。**指定なし → 送付先IDで指定した送付先（未指定なら送付先1）に追加登録**。ダウンロードで確認できる。 |

### 更新可能項目

| 項目 | 内容 | 例 |
|---|---|---|
| お荷物伝票番号 | 全角・半角問わず **120文字以下**。機種依存文字など不正文字は不可。未確定なら空欄可。 | `1000000001` |
| 配送会社 | **数値コード**。未確定なら空欄可。ただし **すでに登録済の情報がある場合は空欄で更新できない**。指定できる配送会社はRMSで事前設定が必要。 | `1003`（日本郵便） |
| 発送日 | `yyyy-mm-dd`（`yyyymmdd` も可）。未確定なら空欄可。 | `2023-08-01` |

### 配送会社コード表（抜粋）

`1000`その他 / `1001`ヤマト運輸 / `1002`佐川急便 / **`1003`日本郵便** / `1004`西濃運輸 /
`1005`セイノースーパーエクスプレス / `1006`福山通運 / `1017`EMS / `1018`DHL / `1019`FedEx /
`1028`Rakuten EXPRESS / `1029`日本郵便 楽天倉庫出荷 / `1030`ヤマト運輸 クロネコゆうパケット …

※1注文あたり送付先IDごとに20個まで登録可能。複数送付先がある注文は送付先ID単位で1つ以上必須。

## 更新パターン（重要）

- **「送付先1」に新規登録**: 送付先ID・発送明細ID の両方が空 → 「送付先1」に追加登録される。
  → 発送明細がまだ無い（発送待ちで一度も伝票番号を入れていない）注文は、この形でよい。
  　CSVは 注文番号 + お荷物伝票番号 + 配送会社(1003) + 発送日 の4つを入れ、送付先ID・発送明細IDは空。
- **登録済みの発送情報を更新**: 送付先が1件でも **送付先ID と 発送明細ID の指定が必要**。
  これらは「発送完了報告用」テンプレートをダウンロードして確認する。
- ⚠ すでに発送明細情報（発送日など）が登録されている送付先に、送付先ID・発送明細ID なしでアップロードすると
  **更新ではなく追加**になり、複数レコード（複数個口）が登録される。二重登録に注意。
- サンプルデータ: `ShippingCompletion_10.zip`（送付先1へ新規）/ `_20.zip`（指定送付先へ新規）/
  `_21.zip`（複数個口）/ `_30.zip`（登録済み更新）/ `_40.zip`（更新＋複数送付先新規）。

## 突き合わせの橋渡し（設計メモ）

アップロード用CSVに宛先列がないため、クリックポスト出力CSV（宛先あり・注文番号なし）と結ぶには
「注文番号 ↔ 宛先」の対応が要る。候補:

1. **LIENmanager が取り込んでいる RMS 注文データ**（注文番号＋送付先氏名/住所/郵便番号）を対応表に使う。
   マスターの追加ダウンロードが不要になる。要確認: 発送待ち注文の送付先項目が揃っているか。
2. **発送完了報告データ(ダウンロード用)** または **通常購入データ** をマスターがダウンロード。
   注文番号＋送付先＋（ダウンロード用なら）送付先ID・発送明細ID が入る。
   → 「登録済み更新」パターンに必要な 送付先ID・発送明細ID もこれで取れる。

どちらを採るか（＝マスターの手数を1回に抑えられるか）は Gram が LIENmanager のコードを見て判断。
