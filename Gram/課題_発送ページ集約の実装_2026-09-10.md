## やること

### 1. ナビゲーションの整理

- サイドバー（`src/components/layout/sidebar.tsx`）から「注文一覧」を削除 → **ダッシュボード / 発送エントリー / レビュー の3項目**。モバイル下部ナビも同様。
- `src/app/orders/`（`page.tsx`）を削除。`/orders` へのリンク・参照を除去。
  - `OrderListTable`（`src/components/orders/order-list-table.tsx`）は**残す**（下記タブ2で流用）。

### 2. 発送エントリー（`src/app/automation/page.tsx`）を上部2タブに

v2 に「注文者情報一覧」が無いため、マスター決定で**上部に2タブ**を付ける:

- **タブ1「作業メニュー」= v2 の中身そのまま**。
  - セグメント: 確認待ち / 未処理 / 作業中 / 処理済み / 一時保存（v2 のとおり。「GoQ」は区切り表示）。
  - 左: 選択中のセグメントの対象リスト（`listTitle` / 件数 / 選択解除 / 行チェック / 行アクション）。
  - 右アサイド: アクション枠（`actionTitle` ＋主 CTA「対象者CSVを作成」など、セグメントで中身が変わる）／取込プレビュー（発送完了報告CSV：最新化→追跡番号CSV取込→発送日→6列SJIS DL）／CSV文字化け警告／本日の履歴。
  - 既存機能を配線: 「対象者CSVを作成」＝現行 `CreateCsvButton`／発送完了報告＝現行 `ShippingReportPanel` の中身／文字化け警告＝現行の `unmappableReport` 表示。
- **タブ2「注文者情報一覧」= 全ステータスの表**。
  - 旧 `/orders` の内容（`OrderListTable` を `filters` 無し＝全件、全列表示で）。
  - v2 のトーンに合わせて枠・余白・見出しを整える。検索（注文番号・氏名）／ステータス絞り込み／並べ替え／ページ送り。
  - この表からも 行チェック→「選択した行でCSVを作成」、各行「一時保存にする」ができる（ブリーフ 5. のとおり）。

### 3. 「一時保存」= 新しい状態（DB1列追加）

- `prisma/schema.prisma` の `Order` に **`heldAt DateTime?`**（nullable）を1列追加＋マイグレーション。
  - ON: 「一時保存にする」を押した時刻。OFF（`未処理へ戻す` / `一時保存から外す`）で null に戻す。
  - 「一時保存から外す」＝ `heldAt` を null にするだけ。注文データは消さない（注文者情報一覧には残る）。
  - RMS同期では `heldAt` を触らない（自動で戻さない／消さない）。
- セグメント/リストの判定:
  - 確認待ち: `orderStatus=100`
  - 未処理: `orderStatus=300` かつ `csvExportedAt` null かつ `heldAt` null
  - 作業中: `csvExportedAt` あり かつ `shippingReportedAt` null（直近7日）
  - 処理済み: `shippingReportedAt` あり（直近7日）
  - 一時保存: `heldAt` あり（期間で絞らない・全件）
- 「未処理をまとめて処理」＝ 現行の全件CSV作成（発送待ち×未出力）から **`heldAt` あり を除外**。
- リポジトリ層（`order.repository`）に必要なカウント/取得メソッドを足す。前回失敗した RMS書き戻しAPIコードには触れない（`shippingReportedAt` は既存＝プロジェクトLで追加済み）。

### 4. 状態設計（各セグメント/ブロックで）

- loading / empty（各リストの空文言）/ error（**RMSと通信できない時は「対象0件」と区別して原因が分かる文言**。`Gram/課題_RMS同期失敗の可視化_2026-09-09.md` と揃える）/ disabled（未処理0件でCTA無効＋理由）/ success（CSV作成後・発送完了報告DL後）。

- Tailwind v4 クラス/トークンへ。インラインスタイルはやめる。アイコンは `lucide-react`。
- ダーク固定・デスクトップ1440px基準。`md` 以下で崩れない程度（モバイル最適化は別）。
- チャート/外部フォント/外部ライブラリの新規追加なし。
- `AGENTS.md`（LIENmanager）: この Next.js は通常と違う。コードを書く前に `node_modules/next/dist/docs/` の該当ガイドを読む。
