# 課題: クリックポストのお問い合わせ番号をRMSへ自動反映する

報告日: 2026-09-07（マスター要望 → フライデー起票）
担当: グラム（LIENmanager）
段階: 未着手。Gate 1（現状確認と実現方法の提示）から。

## マスターの要望

クリックポストに注文者情報を登録してラベルを印字すると「お問い合わせ番号（追跡番号）」が発行される。
現在はこれを1件ずつ手作業で RMS にコピー＆ペーストして発送完了処理をしている。
この反映を自動で行う仕組みを作れるか。可能なら実施したい。

## フライデーの一次確認（2026-09-07）

LIENmanager のコードを見た限り、**この仕組みはかなりの部分が既に実装済み**。ゼロから作る話ではない。

既にあるもの:

- クリックポストのマイページ「発送履歴」からお問い合わせ番号を取得する処理
  （`src/server/integrations/clickpost/clickpost-service.ts` の `fetchTrackingNumbers`）
- RMS の楽天ペイ受注API `updateOrderShipping` を呼ぶクライアント
- 「クリックポストから取得 → RMSへ反映 → 反映済み日時を記録」を通す処理
  （`rms-service.ts` の `reflectTrackingNumber`、`Order.rmsShippingReflectedAt`）
- 1件ずつ反映するAPI（`POST /api/rms/reflect-tracking`）
- 手作業用の「追跡番号をコピー」ボタン（`copy-tracking-number-button.tsx`）

コード内コメントに残る未解決点:

1. **配送会社コード（deliveryCompany）**: RMS固有のコード値で、楽天の非公開ドキュメント依存。
   関数内に推測値を書かない方針のため、正しい値を1つ確定して設定する必要がある。
2. **既に配送情報がある注文の更新挙動が未検証**（コメントに「2026-08-06時点 未検証」）。
   初回登録は想定済みだが、再登録・上書きの挙動を実データで確認していない。
3. **まとめて反映するボタン・画面がない**。今は1件ずつAPIを叩く形。
   「今日の発送ぶんをまとめて反映」の導線が要る。
4. 実際の RMS アカウント＋クリックポストのマイページに対して**通しで動作確認していない**。

## 判断・確認してほしいこと

- 現在の手作業は RMS のどの画面か（受注管理の各注文の配送欄／一括アップロード機能、のどちら）。
- 1日あたりの発送件数と、コピペにかかっているおおよその時間。
- クリックポストは Web 画面だけの利用か（API契約はないという理解でよいか）。
- 楽天ペイ受注API（RMS）は利用申請済みか。追加費用の有無。
  ※ コード上は既に組み込まれているので、たぶん申請済み。グラムに現状を確認させる。

### グラムへ（Gate 1）

- 上記「未解決点」1〜4の現状を確認し、動く状態にするまでに何が要るかを一覧にする。
- 配送会社コードの確定方法（クリックポスト＝どの配送会社扱いか）。
