# 課題: クリックポストのお問い合わせ番号をRMSへ自動反映する

報告日: 2026-09-07（マスター要望 → フライデー起票）
担当: グラム（LIENmanager）
段階: Gate 1 準備中。方針・フローは確定。マスター回答3件取得済み、CSV列見出しのみ未取得（Gramが取る）。

## マスターの要望

クリックポストに注文者情報を登録してラベルを印字すると「お問い合わせ番号（追跡番号）」が発行される。
現在はこれを1件ずつ手作業で RMS にコピー＆ペーストして発送完了処理をしている。
この反映を自動で行う仕組みを作れるか。可能なら実施したい。

## 方針（2026-09-07 マスターと相談して変更）

**API / ブラウザ操作でRMSへ書き戻す方式は前回うまくいかなかった。今回は CSV 変換方式にする。**

- クリックポスト側から、登録済み情報＋お問い合わせ番号（追跡番号）を含む **CSV をマスターが書き出せる**。
- これを LIENmanager に取り込み、注文番号で突き合わせて、**RMS の一括アップロード用 CSV**（お荷物伝票番号の列を埋めたもの）に変換する。
- マスターはその1ファイルを RMS にアップロードして発送処理を一括で済ませる。
- 貼り先は **RMS の「お荷物伝票番号」欄**。

RMS への書き戻し API（`reflectTrackingNumber` / `updateOrderShipping`）と関連導線は今回は使わない
（`order.repository.ts` にも「書き戻しAPI未実装」のコメントあり。深追いしない）。

## フライデーの一次確認（2026-09-07）

- LIENmanager には **クリックポスト「まとめ申込」用の入力CSVを作る機能はある**
  （`src/app/api/clickpost/csv-export/route.ts`、Shift_JIS）。
- **逆方向（追跡番号入りCSV → RMS一括アップロード用CSV への変換）は未実装。** 今回作るのはここ。
- お荷物伝票番号 / RMS一括アップロードに関するコードは現状ない。

## 判断・確認してほしいこと

### クリックポスト出力CSVの形（2026-09-07 マスター提示。実データはチャットのみ・リポジトリには保存しない）

列: `追跡番号, お届け先郵便番号, お届け先氏名, お届け先敬称, お届け先住所, 内容品`

**重要な問題: このCSVに注文番号がない。** 突き合わせできるのは 郵便番号＋氏名＋住所 のみ。
- LIENmanager がクリックポストへ渡す「まとめ申込」入力CSVにも注文番号欄はない
  （`clickpost-types.ts` の `CLICKPOST_CSV_HEADER` は 郵便番号/氏名/敬称/住所1-4/内容品）。
  クリックポストは注文番号を受け取らず・返さない。管理番号のパススルー欄もない。
- 提示データ内に既に反例あり: 同一宛先（同じ郵便番号・氏名・住所）が2行、追跡番号だけ別。
  → 同じ人が同じ期間に2件買うと、どちらの注文にどの追跡番号かを住所氏名だけでは決められない。

### RMS画面の確認結果（2026-09-07 フライデーが Claude in Chrome でマスターの画面を確認）

**RMS には一括アップロード機能がある。** 経路: 受注管理 → 左メニュー「データダウンロード・アップロード」→
「データアップロード（通常購入データ/購入申込データ）」。画面 `csvdl-rp.rms.rakuten.co.jp/rms/mall/csvdl/UL01_01_001`。

- アップロード種別は4つ: 通常購入データ／注文確認データ／**発送完了報告データ**／購入申込データ。
- **お荷物伝票番号と発送日は「発送完了報告データ」CSVに項目がある**（RMS FAQ 000038479 に明記。通常購入データには無い）。
  テンプレート名「発送完了報告用」あり。
- **文字コードは Shift-JIS 必須**（それ以外は処理不可と明記）。
- キーは注文番号。**RMSから発送完了報告データCSVを先にダウンロードすれば、注文番号＋送付先情報が入った状態で取れる。**
  → クリックポスト側に注文番号がなくても、RMS側CSVが注文番号を持つので突き合わせは成立する（注文番号問題は解消）。
- 個別画面（注文詳細）側は、送付先ごとに「配送会社（例: 日本郵便）／お荷物伝票番号／発送日」を入れて
  「入力内容を反映」。いまマスターが1件ずつやっているのはここ。
- FAQに「1つの送付先に対して複数の配送になる場合」「アップロード可能期間」の項目あり（グラムが後で確認）。

### 想定フロー（CSV変換方式）

1. マスター: RMSから「発送完了報告データ」CSVをダウンロード（対象＝発送待ち。注文番号＋送付先が入る）。
2. マスター: クリックポストからレポート出力CSV（追跡番号＋送付先）をダウンロード。← 今のボタンのまま。
3. LIENmanager: 2つを取り込み、**送付先（郵便番号＋氏名＋住所）で突き合わせ**、
   発送完了報告データCSVの「お荷物伝票番号」「発送日」（必要なら「配送会社」）を埋めて Shift-JIS で書き出す。
4. マスター: そのCSVをRMSの「発送完了報告データ」へアップロード。1回で全件反映。

### マスター回答（2026-09-07）

1. **配送会社**: マスターは番号を打つだけで配送会社の設定は不明。「たぶん日本郵便」。
   → Gram が発送完了報告データCSVをDLして、配送会社列が既に入っているか／空で指定必要かを確認する。
2. **発送日** = クリックポストの**登録日**でよい。
3. **件数・時間**: その日の注文はその日に処理。**多い日で1時間くらい**かかる（ここが削減対象）。
4. **受注番号の構成** = `店舗ID(6桁)-YYYYMMDD-xxxxxxx`。
   - xxxxxxx は 7〜20桁のランダム英数字。**xxxxxxx 部分は重複することがある**（全体としてはユニーク）。
   - xxxxxxx の仕様は非公開・予告なく変更あり。
   → 突き合わせ・キーの扱いでは受注番号を**文字列まるごと**で扱う（xxxxxxx だけで判定しない）。
