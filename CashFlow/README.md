# Money（資金繰り・お金の管理）

2026-09-15 起票。プロジェクトNの作業場。詳細・進捗は `Master/プロジェクト一覧.md` の「N. 資金繰り・お金の管理」を正とする（このファイルは重複させず要点だけ）。

## 目的

売上の良し悪しではなく、「今いくら現金があり、この先いくら入って・いくら出ていくか」を見える化する。
支払いに現金が足りなくなる事態（資金ショート）を事前に防ぐことがゴール。

プロジェクトC（`CMO/主力商品_利益記入シート.xlsx`＝主力インナー1個あたりの利益把握）とは視点が異なる。
- C ＝ 商品1個・1注文あたりの単価ベース（商品ページ改善などの判断材料）
- N（このプロジェクト）＝ 会社全体・時期軸での現金の出入り（資金繰り）

費用データ（楽天手数料率・送料・梱包費など）は一部共有できる可能性がある。

## 今わかっていないこと（次に確認すること）

1. **範囲・粒度**: 日次か月次か。まず現状把握（今いくらあるか）の可視化から始めるか、将来の資金ショート予測まで求めるか。
2. **データの入手経路**: 以下がどこにあり、誰が・どう用意できるか。
   - 現在の現金残高（銀行口座）
   - 楽天からの入金サイクルと金額（売上から手数料等を引いた実入金額・入金タイミング）
   - 仕入れ費用の支払いタイミングと金額
   - 固定費（出店費用・システム利用料・その他あれば家賃や人件費など）
   - 税金（消費税・所得税）の積立方針
3. **マスターが把握していない経営数字**があれば `GrandMaster/確認事項.md` へQとして起票する。

## 扱わないこと（当面）

- 税務申告・会計処理そのもの（このプロジェクトは資金繰り＝経営判断用の把握。会計とは分ける方針はプロジェクトCと同じ）。
- 口座番号など個人情報・機密情報そのものの保存。残高・入出金は集計値のみ扱う。

## 進め方

データが揃い次第、プロジェクトCと同様に「記入シート方式」で着手する（実データが集まるまで捏造しない）。
