# 発送ページ集約 ― デザインブリーフ（2026-09-10）

作成: フライデー（マスターとの相談を反映）
用途: Claude Design（デザインキャンバス）に渡して視覚モックを起こすための1枚。
関連: プロジェクトF（運用画面の刷新）の一部。`docs/CODEX_UI_UX_REPORT.md` の方針を踏襲。

---

## 1. 目的・ゴール

発送に使うページを**1つに集約**し、画面上の配置が**そのまま業務フローの順**になるようにする。
「どこで何をするか」を探さずに、上から下へなぞれば発送が終わる状態にしてミスを減らす。

現状は発送関連が2ページに分かれている:

- `/automation`（発送エントリー）… 対象者CSV作成／発送完了報告CSV／処理待ち一覧
- `/orders`（注文一覧）… 全注文の表（RMSとの相違確認用）

→ **`/orders` ページとサイドバーの「注文一覧」項目を廃止**。中身は集約先のタブへ移す。

---

## 2. やること / やらないこと

### やること

- ナビゲーションから「注文一覧」を削除（**サイドバー＝ダッシュボード / 発送エントリー / レビュー の3項目**）。
- 発送エントリーページを**2タブ構成**にする（作業メニュー / 注文者情報一覧）。
- 作業メニューを業務フロー順の縦1本に再構成。発送完了報告CSVパネルもこのフローに統合。
- 「一時保存」という新しい状態を追加（手動退避・手動復帰・手動削除）。
- 「作業中」「処理済み」を状態として区別して表示。

### やらないこと

- 発送処理そのもののロジック変更（対象者CSVの中身、6列CSVの仕様、照合方法は現状のまま）。
- 前回失敗した RMS書き戻しAPIの再開。
- モバイル最適化（デスクトップ1440px・ダーク固定。ダッシュボードC案と同じ前提）。
- 新規チャート／外部フォント／外部ライブラリの追加。

## 3. 画面構成

```
発送エントリー（/automation）
├─ ページ見出し
├─ タブ: [ 作業メニュー ] [ 注文者情報一覧 ]
│
├─ タブ1: 作業メニュー  ← 初期表示。基本ここで作業する
│    （業務フロー順・上から下へ）
│
└─ タブ2: 注文者情報一覧
     全ステータスの注文を1つの表で
```

タブはページ内切り替え（URLは `/automation` のまま、`?tab=` 程度）。ページ遷移はしない。

---

## 4. タブ1「作業メニュー」詳細

**縦1カラム。上から下が発送の実際の手順。** 各ブロックは見出し＋件数バッジ付き。

### (0) 確認待ちの通知（最上部・情報のみ）

- 文言例: `確認待ち 2件 — 自動確認のあと「未処理」に入ります`
- orderStatus=100。操作ボタンなし。0件なら非表示。

### (1) 未処理

- 定義: 発送待ち（orderStatus=300）× CSV未出力 × 一時保存でない。
- **一括アクション**: `未処理をまとめて処理` ボタン → 対象者CSVを作成（＝現状の「対象者CSVを作成」と同じ動作。一時保存の行は除外）。ボタン脇に対象件数を大きく表示。
- 対象0件のときはボタン無効＋理由（`対象がありません`）。
- 一覧（表）: 各行に
  - チェックボックス（選んだ行だけで個別にCSV作成）
  - `一時保存にする` ボタン（その行を「一時保存」へ手動退避）
  - 列: 注文番号 / 注文者 / 郵便番号 / お届け先 / 注文日
- 選択があるときは `選択した◯件でCSVを作成` ボタンを表示。

### (2) 対象者CSVを作成（フロー明示ブロック）

- 上の「未処理をまとめて処理」と同じ機能だが、**フローのステップ1として独立した枠**で見せる。
- サブテキスト: `このCSVをGoQSystemへ読み込ませ、一括申込・一括決済・一括印刷を行ってください。`
- 本日のCSV出力実績（`本日のCSV出力: 12件（最終 14:03・GoQ引き渡し済み）`）。
- CSVに変換できない文字が残った注文の警告（現行のまま。発送は止めない）。

> ※(1)の一括ボタンと(2)は同一機能。モックでは「(1)の未処理リストの上に置く一括ボタン」か「(2)の独立枠」のどちらか一方に寄せてよい。**フローのステップ番号が見えることを優先**。

### (3) 外部作業の区切り（GoQSystem）

- 操作なし。`GoQSystemで 申込・決済・印刷 → 追跡番号入りCSVを書き出す` とだけ示す薄い区切り。

### (4) 発送完了報告CSVを作成（追跡番号のRMS反映）

- 現行の `ShippingReportPanel` をこの位置に移設。
- 手順: `最新化` → クリックポストの追跡番号入りCSVを取込 → 発送日を入力 → プレビュー（自動マッチ / 代表1件 / 要確認 / 未マッチ の件数と中身）→ `発送完了報告CSV（6列・Shift-JIS）をダウンロード` → マスターがRMSへアップロード。
- 二度流し防止済み（`shippingReportedAt`）。手入力済みの行はプレビューでチェックを外せる。

### (5) 作業中

- 定義: CSV出力済み（`csvExportedAt` あり）× 追跡番号の反映が未（`shippingReportedAt` が null）。
- 各行: チェックボックス → `選択した行でCSVを再作成`。
- 意味: 「CSVは出したが、まだ発送完了報告まで終わっていない人」。件数が見えることが主目的。
- 期間: 直近7日。

### (6) 処理済み

- 定義: 発送完了報告まで完了（`shippingReportedAt` あり）。
- 期間: **直近7日**。それより前は「注文者情報一覧」タブで検索。
- 各行: チェックボックス → `選択した行でCSVを再作成`（後からCSVが要るときのため）。

### (7) 一時保存

- 定義: 人が手動で退避した注文（理由は問わない）。
- 期間: **絞らない（全件表示）**。件数は普段少ない想定。多くなってもページ送りで見られる。
- 各行:
  - チェックボックス → `選択した行でCSVを作成`
  - `未処理へ戻す` ボタン（退避を解除して未処理リストへ）
  - `一時保存から外す` ボタン（もう不要になったとき。**一時保存フラグだけ消す**。注文データは残り、注文者情報一覧では引き続き見える）
- 破壊的操作ではないが、`一時保存から外す` は誤操作しにくい位置に置く（行末・小さめ／確認は不要）。

### フロー要約（作業メニューの並び）

```
確認待ち通知
  ↓
未処理  ──(まとめて処理 / 選択して処理)──►  対象者CSV作成  ──► GoQSystem
  │                                                              │
  └──(一時保存にする)──►  一時保存                                 ▼
                          │                              追跡番号入りCSVを取込
                          │(未処理へ戻す / 外す)               ↓
                          ▼                            発送完了報告CSVを作成 ──► RMS
                        （待機）                              ↓
                                                    作業中  ──►  処理済み
```

## 5. タブ2「注文者情報一覧」詳細

- **全ステータスの注文**を1つの表で（確認待ち・発送待ち・発送済・キャンセル 等すべて）。
- 用途: RMSとの相違確認、過去分の検索。
- 列: ステータス / 注文番号 / 注文者 / 郵便番号 / お届け先 / 合計金額 / 支払方法 / CSV出力 / 追跡番号 / 注文日。
- 機能: 検索（注文番号・氏名）、ステータスで絞り込み、並べ替え、ページ送り。
- **この表からも操作できる**: 行チェックボックス → `選択した行でCSVを作成`／各行 `一時保存にする`。
  （作業メニューと同じ操作をこちらでもできる。ただし基本の作業導線は作業メニュー側。）

---

## 6. 「一時保存」= 新しい状態（実装メモ・モックには影響なし）

- アプリに現在この概念はない。データベースの `Order` に手動退避の目印を1列足す想定（例: `heldAt DateTime?`）。
- 手動でのみ ON（`一時保存にする`）、手動でのみ OFF（`未処理へ戻す` または `一時保存から外す`）。
- RMS同期で自動的に戻したり消したりはしない。
- 「作業中／処理済み」の区別は既存の `csvExportedAt` と `shippingReportedAt`（グラムがプロジェクトLで追加済み）で表現でき、新規列は不要。

## 7. モックの状態モデル（props）

- `activeTab`: `menu` / `orders`
- `mode`: `normal` / `loading` / `empty` / `error`
- 件数を振って表示を確認する int: `awaitingConfirmCount`（確認待ち）, `unprocessedCount`（未処理）, `inProgressCount`（作業中）, `doneCount`（処理済み・直近7日）, `heldCount`（一時保存）
- `selectedCount`: 表内で選択中の行数（0で一括ボタンのみ、1以上で「選択して処理」ボタン表示）
- `showCsvSuccess`: bool（CSV作成後の成功表示）
- `shippingReportStep`: `idle` / `loaded`（CSV取込後プレビュー）/ `done`（DL済み）

派生表示:

- `unprocessedCount === 0` → 「未処理をまとめて処理」ボタン無効＋`対象がありません`
- `awaitingConfirmCount === 0` → 確認待ち通知を隠す
- `heldCount === 0` → 一時保存ブロックは「一時保存中の注文はありません」の空状態
- `mode === 'empty'` → 未処理・作業中・処理済みすべて空（「本日の発送作業は完了しています」）

## 8. トークン・スタック（実装の制約）

- 色・間隔・角丸・影・フォントは `src/app/globals.css` の `.dark` トークンから。生 hex を新規に置かない。
  主要: `--primary`（cyan `oklch(0.78 0.13 205)`）, `--surface` / `--surface-elevated`, `--border-subtle` / `--border-strong`,
  `--success-foreground` / `--warning-foreground` / `--error-foreground`（各 `-subtle` / `-border` あり）, `--text-secondary`。
- Claude Design 随伴の `_ds/nocturne-*`（blurple）は**使わない**。アートボードは LIEN 既存トークン（cyan 基調）で描く。
- アイコンは `lucide-react` 相当。
- ダーク固定・1440px 基準。`md` 以下で縦積みに破綻しない程度まで（モバイル最適化は別）。
- 表・長い内容は各自 `overflow-x` の中でスクロール。ページ本体は横スクロールさせない。

## 9. 状態設計（各ブロックで確認できるようにする）

- **loading**: 各リストはスケルトンまたは「読み込み中…」。
- **empty**: 未処理0＝「未処理の注文はありません」／一時保存0＝「一時保存中の注文はありません」／全体empty＝「本日の発送作業は完了しています」。
- **error**: 一覧取得失敗時のメッセージ。**RMSと通信できない場合は「対象0件」と区別して、原因が分かる文言**（`RMSと通信できません（APIキー期限切れの可能性）` ＝ 別課題 `Gram/課題_RMS同期失敗の可視化_2026-09-09.md` と揃える）。
- **disabled**: 未処理0件で一括ボタン無効＋理由。
- **success**: CSV作成後に「◯件をCSVに出力しました」。発送完了報告DL後に「発送完了報告CSVをダウンロードしました。RMSへアップロードしてください」。
