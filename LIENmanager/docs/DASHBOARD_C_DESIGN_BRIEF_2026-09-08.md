## 1. 作るもの

LIEN Manager の運用画面「**今日のオペレーション**」の**高精細な視覚モック**。

- **対象幅: デスクトップ 1440px のみ**（モバイル390pxは今回作らない。方向だけ「Aの縦積み」で確定済み）。
- 一般的な分析ダッシュボードではなく、**発送ミスを防ぎ、今日の作業を終わらせるオペレーション・コックピット**。
- 利用者は **経営者と発送担当を兼ねる1人**。最初に判断できるべきは3点＝「① 今日の処理が残っているか ② そのまま処理できるか（要確認はないか） ③ 次に何をするか」。
- **C案の骨子＝1画面を2ゾーンに分離**:
  - 左ゾーン「**いま やること**」＝発送作業。左だけ見れば作業が回る。
  - 右ゾーン「**きょうの ようす**」＝状況把握。チラ見で当日の異常に気づける。
  - 2ゾーンは背景トーンと1本の細い境界線で視覚的に分ける。左右比＝おおよそ 1.4 : 1。

## 2. デザインシステム（既存 `globals.css` の値をそのまま使う）

アプリは**ダーク固定**（`forcedTheme="dark"`）。ライトテーマは作らない。

**色（CSS変数 = 実値。OKLCH。括弧内は目安の近似hex）**

| 役割 | 値 | 近似hex |
|---|---|---|
| 画面背景 | `oklch(0.115 0.018 255)` | `#0b0f17`（深いネイビー） |
| パネル/カード面 | `oklch(0.175 0.018 255)` | `#151b25` |
| 一段持ち上げた面 | `oklch(0.215 0.022 255)` | `#1c2431` |
| 本文テキスト | `oklch(0.97 0 0)` | `#f4f4f4` |
| 副次テキスト | `oklch(0.80 0 0)` | `#c4c4c4` |
| 無効テキスト | `oklch(0.42 0 0)` | `#5f5f5f` |
| プライマリ（CTA・アクセント） | `oklch(0.78 0.13 205)` | `#2fc7d4`（シアン） |
| アクセント・シアン（補助） | `oklch(0.74 0.11 220)` | `#3fb4cf` |
| 境界・薄 / 濃 | 白 6% / 白 18% | ― |
| 成功 | `oklch(0.78 0.16 155)` | `#2fce8a`（緑） |
| 警告 | `oklch(0.80 0.15 80)` | `#d99a2b`（アンバー） |
| エラー | `oklch(0.72 0.19 25)` | `#f0603f`（赤橙） |
| スキップ/中立 | `oklch(0.60 0 0)` | `#8f8f8f`（グレー） |

- 画面背景にはごく弱い放射グラデーション2つ（右上＝シアン10%、左下＝バイオレット7%）。業務を妨げない範囲。
- **プライマリのシアンとセマンティック色（成功/警告/エラー）は別物**。状態表現にシアンを使わない。

**タイポグラフィ**
- 本文/見出し: `Inter` → `Noto Sans JP` → `Yu Gothic UI` → `Meiryo`
- 数値・時刻・ラベル: 等幅（`SFMono-Regular` / `Cascadia Code` / `Roboto Mono`）。数字は tabular（桁揃え）。
- 見出し・大きな数値は太め、本文は通常、ラベルは中太＋わずかな字間。

**形**
- 角丸: 基本 8px（`--radius: 0.5rem`）。カード 10〜12px。
- 影は最小限。「持ち上げ」はごく浅い影＋面の明度差で表す。ランダムな影値を撒かない。
- アイコンは SVG（Lucide 相当。線幅そろえる）。絵文字をアイコンに使わない。

## 3. レイアウト（C案・1440px）

**上部バー（全幅・固定）**: 左＝現在ページ名「今日のオペレーション」、右＝時刻・自動化の稼働状態（弱いドット＋「稼働中」。赤い「遅延」表示はしない）。

### 左ゾーン「いま やること」（幅 ≈ 58%）

上から縦に:

1. **要確認事項** ― アンバーの左ボーダー3px＋淡いアンバー背景のパネル。件数を見出しに（例「要確認事項　2件」）。各項目は1行＝「内容 / 件数 / （あれば注文番号の末尾）」＋右端に「確認する →」。**0件のときは緑で「確認事項なし」の落ち着いた状態**も設計すること。
2. **現在値タイル 4つ**（2×2）: 発送待ち / CSV未出力 / 本日 発送済み / レビュー未返信。各タイル＝小さいラベル（等幅）＋大きな数値（等幅）＋一言メタ＋アクションリンク（例「一覧を開く →」「CSVを作成 →」）。色ドットで種別を示すが、**色だけに頼らずラベルを必ず添える**。
3. **発送パイプライン**: 「受注確認 → 発送待ち → CSV出力済 → 発送完了」の4段。各段は**段階名と件数を常時表示**（ホバー不要）。同じ幅で件数を比較し、**滞留している段を1つだけアンバーで強調**（小さな「滞留」チップ）。※これは同一コホートのファネルではなく「各段階の現在の件数」。下に一行注記「同じ幅で比較。滞留＝〇〇」。
4. **次の推奨アクション** ― 左ゾーンの下端に固定。シアン寄りの少し持ち上げたカード。等幅の小見出し「次の推奨アクション」＋具体文＋**プライマリボタン1つ**（例「対象者CSVを作成（12件）」）＋補助リンク2本まで。**この画面のプライマリCTAはこれ1つだけ**。

### 右ゾーン「きょうの ようす」（幅 ≈ 42%・背景トーンをわずかに変える）

上から:

1. **本日の処理推移**（中サイズの折れ線・高さ ≈ 210px）:
   - 2本線＝「受注 累計」（点線）と「発送完了 累計」（実線・下に薄い塗り）。時間帯（9〜16時）×件数。
   - **13:00 に締切目安の薄い縦線**（アンバー・破線・ラベル「締切目安 13:00」）。赤いアラートにはしない。
   - **エラー発生を別形状のマーカー＋注記**で（例：13:00 に赤い三角＋「CSV文字化け 1件」）。色だけで表さない。
   - 端点に直接ラベル（「発送 34」「受注 33」）。**凡例は必ず表示**（線種の違いも添える）。
   - グリッドは低コントラスト。タイトル行に「目的・期間・単位・母数」を明記（例「累計 / 9:00–16:00 / 件数 / MOCK」）。
   - 用途は「当日の遅れ・異常の発見」に限定。装飾グラフにしない。
2. **最新アクティビティ** ― 時刻（等幅）＋内容の1行リスト、5件＋「すべて表示 →」。警告系の行はアンバーの文字色で区別。

## 5. 状態設計（各コンポーネントで用意）

- **loading**: スケルトン（数値・行・グラフ枠）。ブランクや無限スピナーにしない。
- **empty**: 要確認0件＝緑の落ち着いた「確認事項なし」／発送待ち0件＝「本日の発送は完了」。アクティビティ0件＝「まだ操作はありません」。
- **error**: グラフ用集計の取得失敗＝「読み込めませんでした」＋再試行ボタン。**原因＋次の操作**をセットで。
- **disabled**: 対象0件のときのCTAは不透明度を下げ、なぜ押せないかを一言。
- **success**: 「対象者CSVを作成」実行後は短い確認（チェック＋トースト）。

## 6. 守るルール / やらないこと

守る:
- 1画面のプライマリCTAは1つ（＝次の推奨アクション）。
- 現在値（左）と過去分析（右のグラフ）を同じ優先度で混ぜない。ゾーンで分ける。
- 状態は色だけに頼らず、アイコン＋文字を必ず添える。
- ホバーが無くても重要情報と操作にアクセスできる。
- `prefers-reduced-motion` を尊重。動きは最小（フェード/わずかな移動のみ、1画面で1〜2箇所）。
- グラフには目的・期間・単位・母数を表示。
- 見出し階層 h1→h2→h3 を飛ばさない。フォーカスリングを消さない。

やらない:
- **既存コードを変更しない**（これは視覚モックのみ）。
- モバイル（390px）は今回作らない。
- 円グラフ。装飾だけのグラフ。根拠のないAIによる評価・予測。
- ライトテーマ。外部フォントの新規追加（既存フォントスタックのまま）。
- 締切超過を赤い「遅延」で煽る表現。
