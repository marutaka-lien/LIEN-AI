## 操作(非エンジニア向け・覚えるのは3つ)

- `cd CEO` … フォルダを移動(例: フライデーと話すなら `CEO` へ)
- `claude` … Claudeセッションを起動(そのフォルダの `CLAUDE.md` と記憶を自動で読む)
- `ls` … フォルダの中身を表示

セッション内で `! <コマンド>` と打つと、そのコマンドを実行して結果を会話に取り込める
(例: `gcloud auth login` のような対話ログイン)。

## 運用サイクル(目標形)

人間が方向を決める → フライデーが全体の優先順位を整理 → マイクが販売面を調査・提案 →
マスター承認 → グラムまたは従業員が実行 → マイクが効果を検証 → フライデーが次の優先順位へ反映。
重要事項は個別AIの記憶だけに置かず、`Shared\` に記録する。
朝は `運用ルーチン.md` の手順で状況確認から始める。

## どこへ保存するか

迷ったときは、次の4つで判断する。

| 内容 | 保存先 |
|---|---|
| 今週何をするか、承認、全員が守る決定 | `Shared\` |
| 全プロジェクトの状態・進捗・積みタスク・将来像 | `Master\プロジェクト一覧.md` |
| 経営責任者に聞くこと、会議で決まったこと、事業の向き | `GrandMaster\` |
| 販売の分析、提案、現在の確認表 | `CMO\` |
| 過去の販売数字、公開レビューなどの元データ | `BusinessData\` |
| アプリ本体と開発資料 | `LIENmanager\` |

同じ内容を複数の場所へコピーしない。元データから分かった結論だけを、担当者の資料へ記録する。

## 原則

- **過剰設計をしない。** 現在の専門エージェントはCEOのフライデー、CMOのマイク、
  実装担当のグラムに限る。追加は必要性が具体化するまで行わない。
- **重要判断は人間。** 業務上の最終判断 / 本番・実データへの重大変更 / 外部サービス仕様の判断 /
  重要な設計・組織方針 は必ずマスター(必要に応じグランドマスター)が決める。
- **この作業スペースに個人情報・機密を置かない。** 顧客の氏名・住所・電話・注文番号や
  認証情報は保存しない。集計値・匿名化データ・件数のみを扱う。
