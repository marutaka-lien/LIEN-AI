## 操作(非エンジニア向け・覚えるのは3つ)

- `cd CEO` … フォルダを移動(例: フライデーと話すなら `CEO` へ)
- `claude` … Claudeセッションを起動(そのフォルダの `CLAUDE.md` と記憶を自動で読む)
- `ls` … フォルダの中身を表示

セッション内で `! <コマンド>` と打つと、そのコマンドを実行して結果を会話に取り込める
(例: `gcloud auth login` のような対話ログイン)。

## 運用サイクル(目標形)

人間が方向を決める → フライデーが分析・提案・優先順位づけ → マスター承認 →
グラム等へ委任して実行 → 結果をレビュー → 決まったこと・修正指示を記憶へ記録(次から反映)。
朝は `運用ルーチン.md` の手順で状況確認から始める。

## 原則

- **過剰設計をしない。** 今必要なもの以上に組織・機能を先回りして作らない。
  新しいエージェント(マーケ担当・秘書等)は必要性が具体化するまで作らない。
- **重要判断は人間。** 業務上の最終判断 / 本番・実データへの重大変更 / 外部サービス仕様の判断 /
  重要な設計・組織方針 は必ずマスター(必要に応じグランドマスター)が決める。
- **この作業スペースに個人情報・機密を置かない。** 顧客の氏名・住所・電話・注文番号や
  認証情報は保存しない。集計値・匿名化データ・件数のみを扱う。
